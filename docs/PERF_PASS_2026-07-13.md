## 2. Network-focused optimization

The server pipeline was audited and is already in good shape — tiered snapshots (player/world/ball
lanes with dirty-keys), per-client backpressure skip, compact codec, perf sampling gated behind
PERF_DEBUG. Per your constraint, no netcode behavior was changed.

The real cost was **client-side, per snapshot-driven frame**:

- **`MultiplayerOverlay.update()` runs every frame (144 Hz)** and previously called
  `summarizeRoom()` — which built the ENTIRE lobby UI as HTML strings (roster, settings panel,
  pregame card, vote controls, and the full post-match report card with team/player stat blocks) —
  **just to compare a change-key and then usually discard everything**. During online play that was
  thousands of discarded string allocations per second (steady GC pressure → frame-time spikes).
- **Fix:** a new `roomSummaryKey()` computes the cheap change-key first; the HTML build now runs
  **only when the key (or another memoized field) actually changes** — i.e. a few times a minute
  instead of 144×/second. DOM behavior is byte-identical (the same key gated DOM writes before).
- The key also now includes the new report-card stats (throws/direct/bounce/curve/backflip) so the
  post-match card can never display stale accuracy.

## 3. FPS-focused findings

- Renderer config was already tuned this week (MSAA 4× native — 8× measured as too expensive in
  dense corner views; 16× anisotropic filtering; half-res SSAO2 with `forceGeometryBuffer`;
  render-once reflection probe; glow layer allow-list). No regressions introduced; nothing further
  changed there in this pass.
- Hot-path audit found the remaining per-frame systems clean: `Hud`/`TeamScoreboard` diff their DOM
  writes, `Scoreboard3D` repaints only on score change, `resolvePolishedConfig()` is never called
  per-frame, mats/dummies/statics are frozen where appropriate.
- Deliberately NOT done (would risk visuals/behavior): `material.freeze()` on gym materials
  (conflicts with the victory-lighting emissive animation), shrinking the mirror/glow render lists
  (visible quality), `scene.skipPointerMovePicking` (the Creator editor picks on pointer-move).

## 4. Honest limits of this pass

- FPS gains here are about **eliminating GC hitches** (client string churn), not raising average
  FPS — the average is GPU-bound and already at your 144 cap; the discarded-HTML fix mainly
  smooths online frame pacing.
- Headless screenshots verify visuals, not frame timing. The definitive check is your own session:
  polished mode should look identical to yesterday, online play should feel the same or smoother.
- The `TeamScoreboard` still rebuilds its (small) markup string per frame before diffing — left
  as-is: low payoff, and a change-key there risks staleness bugs in match-critical UI.
